# Nivesh project guide

This is the implementation guide for the research product as of 13 October 2026. [README.md](README.md) contains the short setup instructions. This document describes implemented behavior separately from future integration work. It contains no account, session, or trade records.

## What the product does

Nivesh is a browser workspace for researching Indian listed companies. A researcher can search for a company, inspect dated quotes and financial statements, compare covered industry peers, review financial checks, model cash flow assumptions, save a watchlist, write research notes, and export tables. The backtester tests explicit daily rules. The trade journal imports validated closed trades or matches execution exports with FIFO.

Numerical calculations run in Python or visible browser formulas. An optional, explicitly requested Gemini deep dive interprets collected reports, provider financials and a pasted filing excerpt; it does not perform financial calculations or live web research. Provider descriptions remain labelled as provider descriptions. The supply-chain graph is generated from freshly collected issuer documents and validated AI extractions, with a separately labelled illustrative sector view. Unknown ownership and filing feeds remain explicitly unavailable. This is a personal research application, not an exchange terminal, execution service, or authenticated investment-account platform.

The legacy SQL does not implement RLS or account integration. `gemini_client.py` supplies thread-safe, process-local credential rotation and cooldowns for the optional deep dive; model selection and response validation live in `deep_dive.py`. Duplicate keys are collapsed. Credential rejections (401/403) disable that key until restart and permit fallback. Quota errors (429) pause all keys with the same project label for at least 60 seconds or the provider Retry-After duration, whichever is longer. Fallback can use a different explicitly labelled project; unlabelled keys conservatively share one quota group. One generation has at most three HTTP attempts with a decreasing 50-second timeout budget. Network failures and model/request/server errors are not automatically replayed, avoiding duplicate generation costs. No model downgrade occurs. HTTPX timeouts apply to network phases, so this budget is not a strict wall-clock cancellation deadline. Counters reset at UTC midnight and are local operational counters, not Google quota accounting. Locks/cooldowns are not coordinated across server processes. Credential contents are excluded from its logs and status output. `Main/` and `.antigravity/` are pre-existing local planning material and are not runtime dependencies.

## Request and data flows

### Company research

1. The browser calls the relative `/api` URL. Next.js forwards it to `BACKEND_URL`.
2. The API client bootstraps `/api/workspace` once before parallel requests. This prevents competing first requests from overwriting each other's new workspace cookies.
3. A company endpoint normalizes the exchange symbol, reads cache if present, and requests only the resolved exchange instrument from Yahoo Finance. It never silently falls back from an Indian symbol to an unrelated unsuffixed overseas symbol.
4. Financial statement series are aligned by the union of actual fiscal-end dates. Missing periods stay null. Amounts are in INR crores, EPS in INR per share, and share counts in units.
5. Derived calculations use matching periods and explicit inputs. The response includes source, quote timestamp when supplied, fetch time, and financial period.
6. Each research tab loads the necessary endpoint when opened. Shared in-flight requests are deduplicated. Late responses from a previous ticker cannot replace the current ticker's view.
7. The browser renders either real data, a loading state, a retryable error, or an explained unavailable state. It does not substitute sample figures after a failure.

Quotes are cached for up to 900 seconds. Charts and financial statements normally use a 3,600-second cache. Empty histories use a short cache. A reload can therefore still use a recent cached response; the source/fetch dates remain visible. Fetch time is not presented as quote time. Provider availability failures return HTTP 503; invalid parameters return 422.

### Research workflow, source collection and company networks

The company page has a Research workflow workspace alongside Supply chain, financials, AI deep dive and notes. This follows a reusable protocol: resolve the issuer; gather evidence; map customers, suppliers and competitors; test financial quality; identify demand, capacity and event exposures; then build conditional scenarios and a falsifiable thesis. Downloading a document does not complete those analytical judgments.

`GET /api/companies/{ticker}/research-workflow` starts collection when there is no current run and returns persisted progress/results. `POST` refreshes it or accepts up to three official report URLs. Discovery queries live NSE annual-report, IPO-document and recent-announcement feeds using the resolved symbol, then follows relevant public investor links from the provider-reported company website. No issuer-specific catalog is used. This works independently of the 61-company screener snapshot. BSE symbols can use company-site discovery and supplied BSE documents; automated BSE feed discovery is not implemented.

Collection uses two background workers with at most eight active/queued issuers, a one-minute manual cooldown and six-hour reuse. It tries up to twelve issuer sources to read six documents; failures trigger alternatives. Different source types retain an annual report/prospectus, current presentation/results, an earnings transcript and company business evidence when available. Actual reports, results, presentations and transcripts outrank routine notices. HTML landing pages retain a separate business-page kind and cannot stand in for an annual PDF; fragment-only navigation is ignored. Newspaper clippings are excluded because they mix unrelated third-party stories with the issuer announcement. Extensionless document endpoints are discovered from link labels. Period hints from labels help sort undated reports; they are not publication dates. Explicit exchange-symbol mismatches and future publication dates are rejected. Reports and evidence are stored in SQLite with PDF hashes, extraction versions, source URLs, publication dates, physical PDF pages, passages, attempts and failures. Interrupted jobs can be retried, and queue submission failures release their slot. Previous-run documents remain separately available for comparison and are excluded from the current graph and AI context. This is a dated source cache, not a saved answer dataset or a claim of complete real-time research.

`filing_sources.py` accepts public HTTPS sources on the reported company domain or NSE/BSE/SEBI domains, checks DNS addresses and each redirect, and bounds streamed downloads to 24 MB. It does not execute page JavaScript, bypass access controls or follow arbitrary external sites. Investor-site CDNs outside those domains may need a future reviewed adapter. Network egress controls are still appropriate for a public deployment; application DNS prechecks alone cannot guarantee protection against all DNS-rebinding scenarios.

`filing_reader.py` reads PDFs and tries up to three PDFs in an IPO ZIP in memory, without extracting archive paths. Unrelated or unreadable archive members are skipped rather than assuming that the largest PDF is correct. Uncompressed archives are limited to 48 MB and reading to 700 pages per file. Identity requires the issuer name as a contiguous phrase in its first three text pages rather than separate name tokens scattered through industry prose. This is a text check, not cryptographic issuer attestation. Unmatched identities, encryption and unreadable/scanned documents become visible errors. OCR and arbitrary PDF table normalization remain unimplemented. Provider tables remain the baseline numerical adapter. A separate conservative income-table parser cross-checks selected issuer rows with explicit basis, periods and units; it does not normalize arbitrary financial PDFs or replace provider values silently.

Relevant passages are grouped into business, procurement/supply chain, competition, demand, risks, governance, financials and policy. Retrieval samples up to three separated matches per category/page, retaining multiple category labels for a short excerpt. Counts and missing categories are visible; matches do not establish analytical completeness. Narrow patterns extract manufacturing/purchase arrangements, procurement brands and customer groups. Sentence-level rejection rules exclude negated, proposed, terminated and explicit third-party mentions; conservative rules can miss valid relationships. Names support Unicode, prepositions, abbreviations and internal legal-name conjunctions. Explicit named customer/supplier lists and numbered issuer tables can create edges. A verified role table can continue onto the immediately following page, keeping the role header in its citation; anonymous Customer No. entries remain unknown. Logos alone do not create edges. Brands, customer groups and community/CSR partnerships have distinct labels. Neither a competitor nor a related party alone becomes a supply edge.

The supply graph is built exclusively from those collected relationships and validated optional AI extractions. Nodes include source passage, physical PDF page and source URL; PDF citations open at the page, while ZIP citations open the original archive. The original company maps remain in `supply_chain_legacy.json` as historical material but are **not loaded by runtime code**. A separately labelled illustrative sector view remains available as a research prompt. Neither extraction path establishes current contracts, completeness or revenue/procurement exposure. Funds retain provider holdings rather than equity supplier graphs.

The Research workflow UI exposes original documents, coverage/errors, classified evidence, six sets of analyst questions, a hypothesis notebook and JSON export. Its editable bear/base/bull learning model calculates a one-year revenue/net-margin/share-count/P-E scenario from reported inputs. Defaults and baseline edits are explicitly user assumptions. The reference share price is the collection-time provider quote, not a fresh quote request; update it before a pitch. It holds current shares constant and does not separately forecast financing, dilution, tax or working capital; banks and insurers are excluded. Missing inputs and non-positive scenario earnings remain explained unavailable states. The hypothesis notebook stays in browser localStorage; notes and scenario inputs are included in exports.

The repository skill at [`.agents/skills/equity-research/SKILL.md`](.agents/skills/equity-research/SKILL.md), created with the skill-creator workflow, supplies the analyst protocol for a Codex-assisted investigation. Its reference covers sector/company selection, peer comparability, demand drivers, policy implementation, financial quality, accounting/valuation differences, contrary evidence and thesis review. It is a Codex instruction skill, not an autonomous runtime agent. The runtime AI prompt uses compatible evidence/hypothesis and causal-analysis rules. Broad industry discovery, global news search, macro time-series joins and policy implementation tracking remain future integrations.

Run `python .agents/skills/equity-research/scripts/research_company.py TICKER --output output/research/TICKER.json` to invoke the same collector from a terminal; add `--source-url HTTPS_URL` when discovery misses an official report. The script does not call AI. It uses live network requests and can take several minutes. Evidence packs and local verification files under `output/research/` are ignored by Git.

### Income-table cross-checks and business-specific diligence

The independent Gem Aromatics, Sambhv Steel Tubes and Hy-Tech Engineers comparison exposed missing counterparties, newspaper contamination, missed transcripts and unconfirmed financial bases. The detailed analysis and sources are in [research/RESEARCH_COMPARISON.md](research/RESEARCH_COMPARISON.md).

`filing_financials.py` accepts only explicit profit-and-loss tables with one stated standalone/consolidated basis, a recognized INR crore/million/lakh unit, unique annual/quarterly periods and aligned numerical rows. Notes and arithmetic references are separate from amounts; parentheses denote losses, dashes remain missing and Cash PAT is never substituted for net income. Ambiguous fiscal ranges, mixed bases, missing units, duplicate rows, unsupported layouts and future periods are skipped. This deliberately favors visible gaps over plausible guesses. It adds a second numerical source for comparison, not a universal PDF table reader.

`financial_reconciliation` retains original provider inputs and the extracted rows, source page, original unit, basis, period and numerical differences. Close values are explicitly marked as having an unconfirmed basis/definition. The learning scenario offers a same-table annual revenue/profit selector; selection and source metadata are exported. It retains separately labelled current shares/price and never silently substitutes cash-flow figures or merges accounting bases. Selecting a table is a researcher choice, not a verification of every accounting judgment.

Issuer organisation/about pages can also supply business evidence. They must remain on the reported company host, contain readable issuer-matched text and pass access-challenge checks. Navigation and controls are removed while ASP.NET form content is retained. Sources are labelled company HTML, with no invented PDF page or publication date. Normalized body hashes and quotations can be checked against re-downloaded pages; promotional claims and current contract status still need review.

The workflow retrieves operations, guidance and concentration passages alongside the existing categories. Boilerplate is down-ranked. Industry templates for steel, chemicals and precision manufacturing, with a general fallback, ask appropriate driver questions and link relevant passages. A common recency check asks whether later filings changed an earlier plan; candidate material filings are dated and labelled as collected or unread. Proposal, approval, incorporation, commissioning and revenue remain different states. Templates are inferred from provider descriptions and may be misclassified; they provide diligence questions, not forecasts or pre-filled company facts.

`research/benchmarks/issuer_cases.json` contains independently reviewed evaluation expectations only. Runtime adapters never import it. `benchmark_research.py` compares exported before/after packs against those selected facts, source-type coverage and retrieval requirements. The resulting score measures that small benchmark, not source completeness, semantic correctness or investment merit. The final 33 selected checks passed, up from eight in the baseline packs. All 18 retained originals and 39 relationship quotations were rechecked. Naming variants and brands may still represent the same legal entity and are not treated as independent exposure weights.

### Official context and repeatable audits

Each collection also reads current PIB/RBI RSS feeds, matches company/industry/sector and macro keywords, and tries at most five article URLs to retain three readable contextual sources. Feeds are reused for one hour. Supply up to three additional `context_urls` on PIB, RBI, MoSPI, Commerce, IMF, World Bank or Federal Reserve domains. Context uses the existing HTTPS/DNS/redirect/download checks with a separate domain allowlist. HTML text is limited to 18,000 characters; access challenges and feed-headline/body mismatches are excluded. ASP.NET form containers are retained while interactive controls are removed. Source dates, unknown dates and future-timestamp/time-zone warnings remain explicit. Headline-only candidates and failed attempts remain visible. Context is an unverified impact lead, never issuer supplier evidence; government announcements alone do not establish eligibility, implementation or materiality. These are public research inputs: do not submit private URLs or credentials.

`GET /api/companies/{ticker}/research-audit` checks current saved evidence against provider tables: finite values, period order/uniqueness, units, baseline differences, citation pages and AI corpus version. The browser's **Run data & evidence checks** button exposes results. Missing values and coverage become warnings, not zeroes. `audit_research.py --verify-originals` re-downloads bounded originals, compares PDF hashes and checks graph quotes on their physical pages. `--pack` audits an exported JSON pack offline without claiming original-source or full-table verification. Passing checks validate contracts and citations, not investment conclusions or publisher accuracy.

AI context uses one evidence snapshot. Cache keys include provider snapshot metadata and a fingerprint of PDF/extraction versions, passages, dates and contextual articles. A transactional SQLite write accepts late AI relationships only when that fingerprint still matches; it cannot overwrite a newer collection. Graphs exclude mismatched AI evidence. Parser upgrades trigger recollection. Private pasted excerpts retain the existing no-public-cache behavior.

### AI interpretation of collected evidence

`GET /api/companies/{ticker}/intelligence` returns the provider summary, collected-document count, AI capability and any cached report without generating output. Explicit generation sends `POST`. The server supplies the business description, selected collected passages and structured provider income/balance-sheet/cash-flow evidence, plus any optional user excerpt. The prompt requests twelve research sections, evidence, open questions and optional explicit relationship extractions.

Pydantic validates structure. Incomplete output and missing/duplicate section IDs reject the response. Individual sections with unknown source IDs, absent quotations or invalid fields are withheld, replaced with explicit evidence gaps, and listed in a visible partial-report notice. Relationships are validated independently and rejected entries are counted in that notice. A failed report with no surviving cited sections is still rejected; a valid all-gap response remains possible when sources establish nothing. Partial reports are not cached, so another explicit generation can retry; accepted relationships still require the existing matching-corpus transaction. Factual `analysis` must equal its cited quotes joined together; unsupported sections must explicitly say that evidence is missing. Model-written qualitative `interpretation` is separately labelled as an unverified hypothesis, requires evidence and cannot contain digits. Numerical claims therefore stay in exact source quotes and deterministic models. This trades fluent factual summaries for a stricter evidence boundary. Relationship checks require the entity, issuer subject, role and non-negated context in the same sentence. External policy sources cannot create issuer edges. These rejection rules do not prove semantic correctness, causal reasoning, completeness, issuer/group scope or accounting judgments.

Reports cache for 24 hours using issuer, model, business-description/financial-period fingerprint and collected-document content IDs. Provider/document-only AI relationships can be saved into the public issuer research result; results involving user excerpts are not saved to that corpus, the shared report cache or the database. Generation responses use `no-store`. Pasted excerpts require a source URL, are disclosed as being sent to Gemini and are not fetched from that URL. Maximum excerpt length is 20,000 characters; source-context budgets and output limits bound individual calls. There is no public per-account quota or distributed abuse protection.

A server-side Gemini key is required only for AI generation. Source collection, extraction, evidence review and scenario arithmetic have been live-tested; AI fallback and evidence validation are tested with controlled responses. These checks do not establish live model interpretation accuracy. The model defaults to `gemini-2.5-flash` and is configurable. Missing keys and provider errors are explicit states.

### Discovery and comparison

The screener reads a persistent snapshot rather than fetching dozens of companies synchronously for every filter change. A bounded worker refreshes the complete bundled symbol list using four provider workers and batches of twelve. A completely failed first batch stops the refresh to avoid flooding an unavailable provider. A process refresh guard limits repeated requests. Manual refresh has a shorter cooldown.

Results disclose covered count, bundled-universe size, refresh state, failed fetches for the current process's last refresh, and fetch dates. This is a curated research universe, not all NSE listings or an official index constituent feed. Search and direct company lookup can resolve instruments outside it. Incomplete coverage is not reported as a market-wide scan.

Numeric filters reject missing inputs. Unknown debt and pledge values do not pass zero-debt or zero-pledge filters. Nulls sort last. Peer comparisons use the same provider industry within the covered snapshot and include the current company; unrelated companies are never substituted when peers are missing. Sector moves are market-cap-weighted over covered companies with valid quotes, not official sector-index performance.

### Private workspace persistence

A random browser identifier is signed with HMAC-SHA256. Its hash is used as the SQLite owner key. The signature is verified before any private read/write. Watchlist, condition, and report queries always include that owner. The browser cannot choose an owner in the request body. Watchlists are unique by owner, list name, and normalized symbol; reports are not publicly readable. Private API responses use `Cache-Control: no-store`.

SQLite is created automatically under `backend/data/nivesh.sqlite3`, or `NIVESH_DATA_DIR`. WAL and a connection timeout support concurrent reads and short writes. The signing secret is supplied through `SESSION_SECRET` or generated into an ignored local file. Keep the database and secret on durable storage, and preserve both for backups. Never commit these files. Existing legacy JSONL reports are not automatically imported because they have no trustworthy owner assignment.

Watchlist entries remain visible when their quotes fail. Saved conditions are evaluated on page reload using the latest cached quote or daily technical bar; the result includes the observed value and observation date. Price/RSI/volume conditions are implemented. No email, push, recurring poll, or notification service is implied.

Research notebooks and saved strategy parameters use browser localStorage. Notes are per normalized ticker and are included in research exports. They are not synchronized to other devices. Trade imports are processed in memory and are not written to the workspace database or sent to an AI provider.

## Numerical contracts and limitations

### Fundamentals and checklist

ROE and payout ratios use provider fractional units, including values above 1.0. Dividend yield is calculated from reported annual dividend per share divided by price, avoiding ambiguous provider yield units. D/E is converted from the provider percentage representation. Three-year revenue and EPS CAGR require actual endpoints approximately three elapsed years apart; a provider quarterly/YoY growth field is not relabelled as three-year growth. Unknown promoter ownership, pledge, and face value stay null. Yahoo insider ownership is displayed separately and is not interpreted as NSE promoter ownership.

The radar is a transparent, fixed-threshold 30-check research checklist. Its API exposes each check, availability, result, and methodology. Missing checks do not pass. Historical growth underlies the growth axis; it is not an analyst forecast. Health checks are not applied to financial institutions or funds. Checklist thresholds are product heuristics, not calibrated investment signals or a recreation of another provider's proprietary score.

### Backtesting

The same Pydantic contract validates natural-language parsing and execution. The text parser handles a deliberately narrow supported grammar and fills a visible builder. It rejects unsupported strategies instead of guessing an unrelated RSI default. The builder supports independent entry/exit RSI, SMA crossover, EMA crossover, MACD, and Bollinger rules with visible periods.

History is requested for the selected dates plus an indicator warm-up period. Indicators require complete windows. Crossovers compare previous and current values; remaining above a threshold is not a new crossing. Signals calculated at a close are shifted to the following open. The portfolio is long only, one position, all available capital reinvested in whole adjusted units. It cannot create a zero-share trade.

Fees and slippage are charged on both sides. Price gaps execute at the opening price when they move beyond a barrier. Daily high/low values are used for stops and targets; when both are touched within the same bar, the stop is assumed first. Remaining positions are liquidated at the final close. Trade returns and P&L include supplied transaction cost assumptions. The exported closed-trade format can be imported into the trade journal.

The equity curve includes cash and marked positions. Drawdown includes initial capital. CAGR uses elapsed calendar time; Sharpe annualizes daily returns at 252 days with a zero risk-free rate. The comparison is the same stock's frictionless buy-and-hold from the first available closing price. Costs are aggregate user assumptions, not an Indian tax calculator. There is no leverage, shorting, derivatives, liquidity/impact model, historical universe, or reconstructed distributed-asset portfolio. Current-symbol research introduces survivorship bias. Pre-NSE stock periods are rejected rather than substituted with a fabricated SENSEX scenario.

Known renames are normalized: ZOMATO to ETERNAL, LTIM to LTM, and the former TATAMOTORS symbol to TMPV. The Tata Motors demerger is explicitly noted in research. Three-year growth and retrospective valuation comparisons are suppressed for this structural break. Ranges spanning its October 2025 transition are rejected because distributed commercial-vehicle shares are not modeled. This is not a complete corporate-action database.

### Valuation and financial screening models

The cash flow calculator starts from reported annual CFO less capex per current share when available, or an explicitly entered user assumption. It never invents cash flow as a percentage of price. A five-year projection plus Gordon terminal value requires positive starting cash flow and a discount rate above terminal growth. It is a simplified equity scenario, not a fully forecast FCFE/FCFF model with debt, dilution, and cash adjustments.

Reverse DCF solves for growth with bisection and an explicit bounded search. Missing/non-positive cash flow and unbracketed solutions remain unavailable. Scenario values display their actual growth and discount assumptions.

Valuation comparisons pair annual EPS/book values with available fiscal-end provider prices and disclose individual observations. Mean plus/minus population standard deviation requires at least three usable annual observations. They are retrospective annual comparisons, not simulated daily history, not necessarily five years, and not point-in-time signals. Provider restatements and inconsistent per-share split conventions can affect comparability. Do not use these observations for historical trading decisions.

Altman uses the four-factor non-financial Z-double-prime screen without an emerging-market rating intercept. Required statement inputs are exposed; no proxy inputs or arbitrary safety constant are substituted. Beneish uses all eight ratios, with the explicitly labelled cash-flow accrual variant of TATA `(net income - operating cash flow) / assets`. Non-positive required ratio denominators and missing/consecutive-period inputs disable the model. CCC uses average opening/closing inventory, receivables and payables with annual revenue/COGS. Financial institutions and funds are excluded from these models. Neither screen is a probability estimate, fraud finding, or India-calibrated risk classifier.

Methodology references: [Altman's NYU paper on distress models](https://archive.nyu.edu/jspui/bitstream/2451/26762/2/S-CDM-02-11.pdf), [Beneish and Nichols on the M-score and its inputs](https://onlinelibrary.wiley.com/doi/full/10.1002/rfe.1182), and the [yfinance history implementation](https://github.com/ranaroussi/yfinance/blob/main/yfinance/scrapers/history.py). Symbol changes were checked against [NSE's TMPV notice](https://nsearchives.nseindia.com/content/circulars/FAOP70882.pdf) and [NSE's LTM disclosures](https://www.nseindia.com/companies-listing/corporate-filings-announcements?symbol=LTM). These sources support method/instrument definitions, not claims that the provider feed or scores are independently audited.

### CSV import and descriptive trade metrics

Closed-trade CSV fields: `ticker,buy_date,buy_price,sell_date,sell_price,qty`, with optional `costs`. Execution exports require symbol, date, buy/sell side, quantity and price. Python's CSV parser supports quoted commas and BOMs. No default prices, quantities, dates or exits are invented. Invalid rows are reported with line numbers. The importer accepts up to 20,000 rows and a 2 MB text field.

Execution matching is FIFO by date and file order. Partial fills become matched observations. Open lots and unmatched sells/short positions are excluded with warnings. Fees are included only when supplied in the closed-trade costs column. Unknown opening positions, short strategies, instrument conversions and broker-specific corporate-action accounting are not reconstructed. A matched lot is not necessarily an independent decision.

The analysis reports recorded P&L, win rate, mean per-observation return, average winner/loser returns and holding days, size CV, observations per week, and a defined size-increase/time-after-loss heuristic. Flat observations are neither wins nor losses. Small and insufficient samples are explicitly labelled. Closed trades do not establish disposition effect, loss aversion or overtrading; those claims were removed. Date-only exports cannot prove intraday sequencing or trading motivation.
